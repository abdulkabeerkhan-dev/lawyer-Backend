# Re-index plan: full-text extraction → structural chunking → re-embedding

Status: **proposed** (2026-11-11). Nothing in Pinecone has been changed.

## Why

Read-only audit findings (2026-11-11):

| Finding | Effect on relevance |
|---|---|
| `case_texts.full_text` for ~139.9k cases labelled `full_judgment` is actually the PakistanLawSite **headnote page** (avg ~3.7k chars; contains "Bookmark this Case"/copyright boilerplate). `holding`, `issues`, `statutory_provisions` are empty in a 2k-row sample. | The model reasons over summaries, not the court's reasoning. Embeddings encode catchwords, not ratio. |
| **Correction:** `case_pdfs` (137,097 rows) is NOT the original judgments. The PDFs were generated by our own scraper from the same web pages (header "Case Index: #N … Pakistan Legal Corpus"); median 5 KB / 1 page. 2 are empty; some are the site's "Error Code:700" page. | PDF extraction will not recover full judgments for most cases. |
| Content classification of all 141,481 `case_texts` rows: **128,421 headnote-only (91%)**, 9,364 likely full judgments (mostly PLD 4,864 and MLD 4,454; SCMR only 6; PCRLJ only 7), 811 scraper error pages, 1,322 empty stubs. | Answers are written from headnotes. Retrieval over headnotes can still be good (headnotes are what lawyers search), but reasoning quality is capped until full judgments are sourced. |
| Production keyword search (`bm25_index.pkl`) covers **9,749 cases (~7%)**: 6,190 PLC(CS), 0 PCRLJ; none of the key bail/489-F authorities; includes 2026 SCMR 1160 (an irrelevant case the bail memo cited). Metadata wrong (court/year). | Hybrid fusion (RRF) rewards whatever is in this skewed slice. |
| 87% of cases have `court_name = "High Court / Appellate Tribunal"`; ~400 rows have garbage year/journal. | No court filtering/authority ranking possible. |
| Turso FTS index was empty; `search_cases_fts()` is never called. | Keyword search over Turso unavailable. (Index rebuilt 2026-11-11.) |

## Phases

Each phase ends with the golden-set eval (`python -m eval.retrieval_eval`). Do not start the next phase if recall did not improve.

### Phase 0 — Golden set (prerequisite, 2–3 days, needs a lawyer)
- 60–100 real queries across criminal (bail, 302, 489-F, CNSA), civil (partition, specific performance, limitation), family, rent, banking, service, constitutional.
- For each: 3–10 must-retrieve citations, verified by a lawyer against the primary source (not by an LLM), plus must-not-appear items.
- Seed: the 302 bail and 489-F queries (authorities confirmed present in Turso: 2024 SCMR 14, 2025 SCMR 129, 2010 SCMR 806, 2023 SCMR 2122, 2023 SCMR 1948).
- Metrics: Recall@10, Recall@50, MRR, and "wrong-domain in top 10" rate.

### Phase 1 — Clean and enrich what we have (no new data needed)
- Exclude the 811 error pages and 1,322 empty stubs from indexing; re-scrape them.
- Clean with `HierarchicalLegalChunker.clean_portal_debris` (strips portal boilerplate) when building index text. Source rows are not overwritten.
- Set `content_level` honestly (`headnote_only` vs `full_judgment`) so the memo never presents a headnote as a judgment.
- Court: the scraped header carries it (e.g. `KARACHI-HIGH-COURT-SINDH`, `PESHAWAR-HIGH-COURT`). Parse into Lahore/Sindh/Peshawar/Balochistan/Islamabad HC, SC, FSC, tribunals. Fix garbage year/journal from the citation.
- Headnote catchwords already list statutes (`Criminal Procedure Code (Cr.P.C) 1898--497`): parse into canonical statute IDs and a domain tag.

### Phase 1b — Source full judgments (business decision)
- Only ~9.4k full judgments exist. Options: official court websites (SC and High Courts publish judgments, mostly recent years), a licensed feed from a law reporter, or a partnership. Licensing needs to be settled before selling (see Open decisions).

### Phase 2 — Structural chunking + metadata
- Use the existing `StructuralJudgmentSegmenter` / `HierarchicalLegalChunker`: headnote, facts, issues, arguments, reasoning, holding/order. No fixed 512-token windows across section boundaries.
- Every chunk carries: `case_id, citation, court, court_level, year, journal, section_type, domain, statutes[] (canonical IDs, e.g. CRPC_1898_SEC_497), disposition`.
- Prefix chunk text with a short context header: `[2024 SCMR 14 | Supreme Court | Bail — s.497 CrPC | Reasoning]`.

### Phase 3 — Re-embed into a NEW namespace
- Embed with `voyage-law-2` into namespace `judgments_v2`. Leave `judgments` untouched until v2 beats it on the golden set, then flip `PINECONE_NAMESPACE`.
- Cost estimate: see "Sizing" below.
- Metadata filters at query time: `domain`, `statutes`, `court_level`, and `section_type` (e.g. prefer `reasoning`/`holding`).

### Phase 4 — Keyword search over the full corpus
- Replace the 9.7k-case `bm25_index.pkl` with Turso FTS5 over `case_fulltext` (or a BM25 index rebuilt from all chunks).
- Fix `search_cases_fts` query construction: currently ANDs every word of the user's question, which matches almost nothing for natural-language queries. Use extracted legal terms (sections, statutes, doctrine terms) with OR plus phrase boosts.

### Phase 5 — Ranking
- Re-tune fusion and cross-encoder reranking on the golden set; add metadata-based hard filters from the query planner (domain/statute) before reranking.
